# Security policy

Please do not open a public issue for a vulnerability that could put an installation or its data at risk.

Use GitHub's private vulnerability reporting feature for this repository. Include the affected version or commit, the conditions required to reproduce the problem, the likely impact, and any mitigation you have already tested.

Never include real access tokens, passwords, session keys, household data, or private network details in a report. Replace them with clearly marked examples.

Security fixes are developed privately until a patch and upgrade guidance are ready. There is no guaranteed response time, but reports with a clear reproduction are easier to investigate quickly.
